# Deploying Sellandiamman Estates

One server runs everything: the public website, the staff workspace (`/erp`), the owner portal (`/owner`), the investor
dashboard (`/investor`) and the API, behind one HTTPS address. Caddy gets and renews the certificate automatically.

```
Internet ──443──▶ Caddy (web)  ─┬─ website pages ─▶ backend adds title, text and schema.org data to index.html
                                │                   (plain index.html if the backend is busy, so the site never goes blank)
                                ├─ /static, /images  built app files
                                ├─ /api/*            ─▶ backend (FastAPI)  ─▶ MongoDB
                                ├─ /s/*              link previews for WhatsApp / Facebook shares
                                └─ /robots.txt, /sitemap.xml, /llms.txt (generated by the backend)
                     backup ─▶ nightly database dump + uploaded files in ./backups
```

The web container copies the built `index.html` into a shared volume (`site_shell`) at start-up; the backend reads it from
there to serve each page with its own text. Nothing to configure.

## 1. What you need

- A Linux server (Ubuntu 22.04/24.04), 2 GB RAM and 20 GB disk is enough to start. Any Indian region of a cloud host works.
- A domain, with an **A record** for `www.yourdomain.in` (or the bare domain) pointing at the server's IP.
- Ports **80 and 443** open in the server firewall.
- Docker: `curl -fsSL https://get.docker.com | sh`

## 2. Configure

```bash
git clone https://github.com/prathipanshanmugham/sellandiamman-estates-.git estates && cd estates
cp .env.example .env
cp backend/.env.example backend/.env
```

**`.env`** (read by Docker Compose)

| Setting | Value |
|---|---|
| `DOMAIN` | `www.yourdomain.in` – exactly the name in your DNS record |
| `ACME_EMAIL` | Your email, for certificate notices |
| `MONGO_PASSWORD` | Long random value: `openssl rand -hex 24` |

**`backend/.env`** (only these lines matter with Docker; the rest come from `.env`)

| Setting | Value |
|---|---|
| `JWT_SECRET` | `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `ADMIN_EMAIL` | The first administrator's email |
| `ADMIN_PASSWORD` | A strong temporary password (10+ characters). Remove it after the first sign-in. |
| `SEED_DEMO` | `false` |
| `VAULT_KEY` | `openssl rand -base64 32` – encrypts the password vault. **Keep a copy off the server** (sealed envelope or your own password manager) and never change it once logins are saved. |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | Your mail provider (Zoho Mail, Google Workspace, Amazon SES, Brevo…). Without these, password links are shown on screen for an admin to share. |
| `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET` | Optional: free Cloudflare Turnstile keys for an "I am human" check on public forms |

## 3. Start

```bash
docker compose up -d --build
docker compose ps          # all services "running" / "healthy"
docker compose logs -f web # watch the certificate being issued (first start only)
```

Open `https://www.yourdomain.in`, then `https://www.yourdomain.in/erp/login`.

## 4. First sign-in (do these in order)

1. Sign in with `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
2. **Security** (key icon, top right): change the password, then **turn on 2-step sign-in** with Google or Microsoft Authenticator. Keep the recovery codes off the phone.
3. Remove `ADMIN_PASSWORD` from `backend/.env` and run `docker compose up -d backend`.
4. **Settings**: work through the **Go-live checklist** at the top – real phone/WhatsApp/email/address, TNRERA agent number, GST (ask your accountant before turning it on), social links, reviews.
5. **Settings → Security & alerts**: require 2-step sign-in for at least Super Administrator, Director and Accountant.
6. **Users & Roles**: create staff accounts. Without a password they get a one-time link to set their own (emailed when SMTP is set, otherwise shown for you to send on WhatsApp).
7. **Branches & places** (`/erp/places`): replace each branch's placeholder address with the real one, add its phone,
   WhatsApp, email, office hours and Google Business Profile link, and set Kadambur's PIN code and map point (left
   blank). Check the head office. Then set each manager under Users & Roles (branch, designation, reports to).
8. **Settings**: agreement signatory and designation, monthly revenue targets per branch and, if you like, the CEO
   health-score weights.
9. **Settings → Rent collection account**: the UPI ID and bank details tenants pay rent and bills to (the owner-funds account).
10. **Customer logins**: from a customer, lease, owner or investor record (or **Users & Roles → Customer login**) give tenants,
   owners (lessors), buyers and investors their own sign-in. They set a password from the link (valid 7 days) and sign in
   at `/login`.
11. **Password vault** (`/erp/vault`): add the company's platform logins and share each with the roles that need it.
12. Add properties, verify ownership, record the marketing authorisation, then publish.

## Sharing a server that already runs nginx

If other websites on the server already use nginx (ports 80 and 443 taken), let nginx handle HTTPS and pass this site to
the Docker stack on a local port:

1. Add to `.env`: `SITE_ADDRESS=:80`, `HTTP_BIND=127.0.0.1:8088`, `HTTPS_BIND=127.0.0.1:8443`, then
   `docker compose up -d --build`.
2. `cp deploy/nginx-estates.conf /etc/nginx/sites-available/sellandiammanestates` (change the domain if needed),
   link it into `sites-enabled`, `nginx -t && systemctl reload nginx`.
3. `certbot --nginx -d www.<domain> -d <domain> --redirect`.
4. Check that plain http is sent to https: `curl -s -o /dev/null -w "%{http_code} %{redirect_url}\n" http://www.<domain>`
   must print `301 https://www.<domain>/`. If it prints `200`, install the finished file instead:
   `sudo tee /etc/nginx/sites-enabled/sellandiammanestates < deploy/nginx-estates-https.conf`, then
   `nginx -t && systemctl reload nginx`. Updates never need the nginx file copied again (copying the first file over
   the finished one removes HTTPS).

The bare domain is redirected to `www` by the app. Visitors' real addresses reach the backend (Caddy trusts only the
private Docker address nginx connects from), so rate limits and the audit log stay per visitor.

## 5. Short-stay calendars (Airbnb, Booking.com, Agoda, MakeMyTrip…)

For each home, under **Short stays → Homes & platforms**:

1. Add the platforms the home is listed on (the usual commission is filled in; change it to your contract rate).
2. **Their calendar → us**: in the platform's host calendar, find "Export calendar" / "iCal link", copy it and paste it here.
   It is read every 15 minutes (and on "Sync now"). New reservations appear marked "add guest details".
3. **Our calendar → them**: copy our link for that platform and paste it in the platform's "Import calendar". Each
   platform gets its own link, so it does not see its own bookings twice. Use "New link" if a link is ever shared by mistake.
4. Platforms read imported calendars on their own schedule (often every 1–3 hours), so a booking made elsewhere can take
   that long to close there. The dashboard flags any double booking at once.

## 6. Search engines and AI assistants

- Add the site in **Google Search Console** and **Bing Webmaster Tools** and submit `https://<domain>/sitemap.xml`.
- Put each branch's Google Business Profile link in Branches & places; the website lists the branches with their
  addresses and links them to their profiles.
- `robots.txt` lets search engines and AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended and others) read
  the public pages and keeps `/erp`, `/owner`, `/investor` and the API out. `llms.txt` gives assistants a short guide.
- Write Insights about each town; the town and locality pages (`/properties-in/<town>/<locality>`) update themselves
  as listings change.

## 7. Backups

The `backup` service writes `backups/db-<date>.gz` and `backups/uploads-<date>.tgz` at start-up and every night at 02:30 IST,
keeping 30 days (`BACKUP_KEEP_DAYS`). **Copy them off the server** – a backup on the same disk does not survive a lost server:

```bash
# Example: nightly copy to Google Drive / S3 / another machine with rclone (configure rclone once)
0 4 * * * rclone copy /home/ubuntu/estates/backups remote:estates-backups --max-age 48h
```

Restore (replaces the live data – rehearse it once on a spare server):

```bash
./scripts/restore.sh backups/db-2026-10-17_2100.gz backups/uploads-2026-10-17_2100.tgz
```

Manual backup at any time: `docker compose exec backup bash /scripts/backup.sh /backups`

## 8. Updating

```bash
git pull
docker compose up -d --build
```

New database indexes and settings are created automatically on start. Nothing is deleted.

**Round 5 (password vault):** add a vault key once, before or after updating, and keep a copy off the server:

```bash
echo "VAULT_KEY=$(openssl rand -base64 32)" >> backend/.env
grep VAULT_KEY backend/.env      # copy this line somewhere safe, away from the server
docker compose up -d --build
```

Without `VAULT_KEY` everything else works and the vault page shows how to switch it on.

Updating from Round 2
creates the five branches, puts existing records in the branch for their town (head office when unknown), builds the
customer list from leads, owners, tenants and guests, and seeds the website editor from your Settings.

## 9. Good to know

- **One backend process.** Reminders run inside the backend and sign-in rate limits are kept in memory, so keep one backend container. Add Redis before running several.
- **Times** are shown in IST everywhere; the server clock can stay in UTC.
- **Uploaded files** (documents, photos) live in the `uploads` Docker volume, are never public unless a photo is approved for the website, and are downloaded through 5-minute signed links.
- **Maps** use OpenStreetMap tiles. For heavy traffic, use a tile provider with a key: set `MAP_TILES` / `MAP_ATTRIBUTION` in `.env` and add its host to `img-src` in `deploy/Caddyfile`.
- **Link previews**: share buttons use `https://<domain>/s/p/<listing>` so WhatsApp shows the photo, price and title.
- **Search engines**: `/sitemap.xml` lists every published listing and article; submit it in Google Search Console.
- **Location capture** (GPS on phones) needs the site on HTTPS, which Caddy provides; the browser asks the person first.
- **Password vault**: secrets are encrypted with `VAULT_KEY` (AES-256-GCM); the database and its backups alone do not reveal
  them. Keep the key and the backups in different places. Unlocking needs the person's own password (and 2-step code), lasts
  15 minutes, and every view, copy, code and change is in the vault's activity tab and the audit log.
- **Customer portals**: tenants (`/tenant`), owners / lessors (`/owner`), buyers (`/buyer`) and investors (`/investor`) each
  sign in from `/login`; staff sign in from `/erp/login` (link in the website footer).
- **Logs**: `docker compose logs --tail 200 backend` (emails sent, reminders, errors). Health: `https://<domain>/api/health`.

## 10. Running without Docker (development)

```bash
# backend
cd backend && pip install -r requirements-dev.txt
cp .env.example .env   # MONGO_URL=mongomock://local uses an in-memory database for trying things out
uvicorn server:app --port 8001 --reload
# frontend (proxies /api to :8001)
cd frontend && yarn install && yarn start
# tests (backend running with SEED_DEMO=true)
cd backend && python -m pytest tests -q
```

## 11. Troubleshooting

| Problem | Fix |
|---|---|
| Certificate not issued | DNS must point at the server and ports 80/443 must be open. Check `docker compose logs web`. |
| "Origin not allowed" on forms | `DOMAIN` in `.env` must match the address in the browser (www vs bare domain). Redirect one to the other in `deploy/Caddyfile`. |
| Locked out of admin | Set `ADMIN_PASSWORD` and `ADMIN_RESET_PASSWORD=true` in `backend/.env`, `docker compose up -d backend`, sign in, then remove both. |
| Lost phone with 2-step sign-in | Use a recovery code, or another administrator resets it under Users & Roles. |
| A platform's calendar does not sync | Short stays → Homes & platforms shows the last sync and the error. The link must be the platform's iCal export link (https). If the platform blocks our server, download the .ics file there and upload it with the ".ics file" button next to that platform. |
| Pages show without their text when JavaScript is off | Check `docker compose logs web` for the `cp /srv/index.html` step and that the backend has `SITE_SHELL` set (it is in docker-compose.yml). |
| Emails not arriving | Check `docker compose logs backend | grep -i email` and the SMTP settings; Settings → Go-live checklist shows whether email is set up. |
