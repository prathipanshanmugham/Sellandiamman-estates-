# Deploying Sellandiamman Estates

One server runs everything: the public website, the staff workspace (`/erp`), the owner portal (`/owner`) and the API,
behind one HTTPS address. Caddy gets and renews the certificate automatically.

```
Internet ──443──▶ Caddy (web)  ─┬─ /            built website + staff app + owner portal
                                ├─ /api/*       ─▶ backend (FastAPI)  ─▶ MongoDB
                                ├─ /s/*         link previews for WhatsApp / Facebook shares
                                └─ /robots.txt, /sitemap.xml (generated by the backend)
                     backup ─▶ nightly database dump + uploaded files in ./backups
```

## 1. What you need

- A Linux server (Ubuntu 22.04/24.04), 2 GB RAM and 20 GB disk is enough to start. Any Indian region of a cloud host works.
- A domain, with an **A record** for `www.yourdomain.in` (or the bare domain) pointing at the server's IP.
- Ports **80 and 443** open in the server firewall.
- Docker: `curl -fsSL https://get.docker.com | sh`

## 2. Configure

```bash
git clone https://github.com/prathipanshanmugham/sellandiamman-estates-.git estates && cd estates
cp .env.example .env
cp backend/.env.example backend/.env
```

**`.env`** (read by Docker Compose)

| Setting | Value |
|---|---|
| `DOMAIN` | `www.yourdomain.in` – exactly the name in your DNS record |
| `ACME_EMAIL` | Your email, for certificate notices |
| `MONGO_PASSWORD` | Long random value: `openssl rand -hex 24` |

**`backend/.env`** (only these lines matter with Docker; the rest come from `.env`)

| Setting | Value |
|---|---|
| `JWT_SECRET` | `python3 -c "import secrets; print(secrets.token_urlsafe(48))"` |
| `ADMIN_EMAIL` | The first administrator's email |
| `ADMIN_PASSWORD` | A strong temporary password (10+ characters). Remove it after the first sign-in. |
| `SEED_DEMO` | `false` |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM` | Your mail provider (Zoho Mail, Google Workspace, Amazon SES, Brevo…). Without these, password links are shown on screen for an admin to share. |
| `TURNSTILE_SITE_KEY`, `TURNSTILE_SECRET` | Optional: free Cloudflare Turnstile keys for an "I am human" check on public forms |

## 3. Start

```bash
docker compose up -d --build
docker compose ps          # all services "running" / "healthy"
docker compose logs -f web # watch the certificate being issued (first start only)
```

Open `https://www.yourdomain.in`, then `https://www.yourdomain.in/erp/login`.

## 4. First sign-in (do these in order)

1. Sign in with `ADMIN_EMAIL` / `ADMIN_PASSWORD`.
2. **Security** (key icon, top right): change the password, then **turn on 2-step sign-in** with Google or Microsoft Authenticator. Keep the recovery codes off the phone.
3. Remove `ADMIN_PASSWORD` from `backend/.env` and run `docker compose up -d backend`.
4. **Settings**: work through the **Go-live checklist** at the top – real phone/WhatsApp/email/address, TNRERA agent number, GST (ask your accountant before turning it on), social links, reviews.
5. **Settings → Security & alerts**: require 2-step sign-in for at least Super Administrator, Director and Accountant.
6. **Users & Roles**: create staff accounts. Without a password they get a one-time link to set their own (emailed when SMTP is set, otherwise shown for you to send on WhatsApp).
7. **Owners**: invite owners to the owner portal from each owner's record.
8. Add properties, verify ownership, record the marketing authorisation, then publish.

## 5. Backups

The `backup` service writes `backups/db-<date>.gz` and `backups/uploads-<date>.tgz` at start-up and every night at 02:30 IST,
keeping 30 days (`BACKUP_KEEP_DAYS`). **Copy them off the server** – a backup on the same disk does not survive a lost server:

```bash
# Example: nightly copy to Google Drive / S3 / another machine with rclone (configure rclone once)
0 4 * * * rclone copy /home/ubuntu/estates/backups remote:estates-backups --max-age 48h
```

Restore (replaces the live data – rehearse it once on a spare server):

```bash
./scripts/restore.sh backups/db-2026-10-17_2100.gz backups/uploads-2026-10-17_2100.tgz
```

Manual backup at any time: `docker compose exec backup bash /scripts/backup.sh /backups`

## 6. Updating

```bash
git pull
docker compose up -d --build
```

New database indexes and settings are created automatically on start. Nothing is deleted.

## 7. Good to know

- **One backend process.** Reminders run inside the backend and sign-in rate limits are kept in memory, so keep one backend container. Add Redis before running several.
- **Times** are shown in IST everywhere; the server clock can stay in UTC.
- **Uploaded files** (documents, photos) live in the `uploads` Docker volume, are never public unless a photo is approved for the website, and are downloaded through 5-minute signed links.
- **Maps** use OpenStreetMap tiles. For heavy traffic, use a tile provider with a key: set `MAP_TILES` / `MAP_ATTRIBUTION` in `.env` and add its host to `img-src` in `deploy/Caddyfile`.
- **Link previews**: share buttons use `https://<domain>/s/p/<listing>` so WhatsApp shows the photo, price and title.
- **Search engines**: `/sitemap.xml` lists every published listing and article; submit it in Google Search Console.
- **Logs**: `docker compose logs --tail 200 backend` (emails sent, reminders, errors). Health: `https://<domain>/api/health`.

## 8. Running without Docker (development)

```bash
# backend
cd backend && pip install -r requirements-dev.txt
cp .env.example .env   # MONGO_URL=mongomock://local uses an in-memory database for trying things out
uvicorn server:app --port 8001 --reload
# frontend (proxies /api to :8001)
cd frontend && yarn install && yarn start
# tests (backend running with SEED_DEMO=true)
cd backend && python -m pytest tests -q
```

## 9. Troubleshooting

| Problem | Fix |
|---|---|
| Certificate not issued | DNS must point at the server and ports 80/443 must be open. Check `docker compose logs web`. |
| "Origin not allowed" on forms | `DOMAIN` in `.env` must match the address in the browser (www vs bare domain). Redirect one to the other in `deploy/Caddyfile`. |
| Locked out of admin | Set `ADMIN_PASSWORD` and `ADMIN_RESET_PASSWORD=true` in `backend/.env`, `docker compose up -d backend`, sign in, then remove both. |
| Lost phone with 2-step sign-in | Use a recovery code, or another administrator resets it under Users & Roles. |
| Emails not arriving | Check `docker compose logs backend | grep -i email` and the SMTP settings; Settings → Go-live checklist shows whether email is set up. |
